# Public Offer Contract v1

この文書は、意思決定UIへ渡す公開用旅行オファーデータの契約です。DBそのもの、認証情報、runtime snapshotは公開しません。

## 目的

DBの正式情報 → 公開許可項目だけのJSON → 地図 / 宿泊日 / 予約先比較、の境界を固定します。

この契約で最優先するのは「表示できる情報量」ではなく、ユーザーへ誤って「使える」「足せる」「最安」と伝えないことです。

## v1 の必須ルール

1. `booking_start/end` は予約できる期間で、宿泊対象期間とは別物。
2. `stay_window.mode=provider_plan_availability` の施策は、旅行日だけで適用確定しない。
3. `property_scope` が限定・除外ありなら、施設 / プラン確認前は `eligible` にしない。
4. `benefit.rate_semantics=minimum_total` の数値は下限表示。「15％以上」を正確な15％として順位付けしない。
5. `benefit.includes_offer_ids` に入る施策は内包関係。率を加算しない。
6. `stacking.mode=exclusive_best_campaign` の施策同士は重複適用しない。
7. `instant_or_later` は「今回値引き」と「後日ポイント」のどちらにもなり得る。両方を同時に得るものとして二重計上しない。
8. `match_requirements` が1件でも未確認ならUIは「追加条件確認」とし、「使える」と断定しない。
9. 実価格・在庫が無いLevel 1では実質支払額の順位、最安、通常価格差を表示しない。
10. 出典URL・出典更新日・確認時点を必須にする。不明値を0/falseで埋めない。
11. 根拠URLと予約先URLを分離する。`booking.provider_url` は公式予約先のfallback、`booking.tracking_url` は任意の成果計測URLとする。`tracking_url` はDBの有効な `affiliate_links` から、提携条件確認済み・リンク確認済み・有効期間内の場合だけ公開し、推測生成しない。`booking.monetization=affiliate` の時だけUIが `tracking_url` を優先し、リンクには `rel="sponsored noopener noreferrer"` を付ける。未登録時は従来どおり公式予約先へ送る。
12. Level 2の推定割引額は `coupon_rate` / `coupon_fixed` のように単独クーポンとして計算条件が構造化されたものだけ。最低利用額、JPY通貨単位、計算基準（eligible_stay_amount）、率型は丸め規則と上限有無まで確認済みでなければ計算しない。PayPayポイント等の `paypay_total_rate` を「割引額」に機械換算しない。
13. 共有URLは destination / month / date / adults / children / provider / view / price の旅行条件だけを持ち、認証情報・DB・ログ・内部IDを入れない。

## 現在の公開サンプル

`decision-data.json` のYahoo!トラベル宿泊2施策を契約サンプルにしています。

- 「いつでも誰でも10％お得」は一部対象外施設があり、オンラインカード決済等を確認してから適用確定。
- 「人気宿スペシャル 15％以上」は対象施設・プラン限定で、基礎10％を含む総率。別加算しない。
- 人気宿スペシャルの宿泊期間は「対象プランの予約可能期間に準ずる」ため、選択旅行日だけでは適用確定しない。

## UIが返す判定

現行入力（地域・旅行日・大人人数）だけでは、上記2施策は次のどちらかです。

- `scheduled`: 予約開始前。
- `needs_more_data`: 施設 / プラン / 支払方法等が不足。

`eligible` は将来、必要条件がすべて既知かつPASSした時だけ返します。

## 順不同の検索軸・共有URL

地図・日付・旅行会社は、前提条件なしでいつでも選べる独立した検索タブです。注目のキャンペーンは別タブで一覧できます。

- 地域未定で日付を選んでも、カレンダーのまま日付を保持します。
- 地域・日付未定で旅行会社を選んでも、その会社の特典を探せます。
- 地域・日付・旅行会社の変更は現在のタブを変更しません。
- 各条件は解除でき、検索タブを切り替えても保持します。
- `view=map|date|provider|campaign` で表示タブを共有し、条件の有無から表示タブを推論しません。
- 大人1〜9人・子供0〜6人は検索条件の保持用です。施設の年齢区分・子供料金・適用判定は未連携です。
- 共有URLは保存済み条件より優先され、指定されていない条件を別セッションから引き継ぎません。

## デザイン用サンプル

`design-samples.json` は公開契約の実データから分離した架空の特典です。各レコードに `sample: true` を付け、全表示・詳細・試算でサンプルと明示し、予約先リンクを持たせません。実データの出典・適用状態・ポイント内包関係は変更しません。

サンプルは地域、旅行会社、サンプル宿泊期間で絞り込みます。日付が未定の場合は表示月でサンプル期間を絞ります。実データの予約受付期間を宿泊期間として流用せず、施設・プラン不明の施策は条件確認が必要な候補として表示します。カレンダーの件数はサンプルを含む候補数で、価格・在庫・適用確定を意味しません。

季節のカルーセルは6秒で自動切り替えします。手動切り替え・停止に対応し、マウス滞在、キーボードフォーカス、非表示タブ、動きを減らす設定で自動切り替えを止めます。リンクは `sample-campaign.html?campaign=...` の特集ページへ遷移し、戻る操作と検索条件への反映で既存条件を保持します。

## Level 2 / Level 3

Level 2で対象宿泊料金を入力して推定額を出す場合も、単独クーポンの率 / 額 / 上限 / 最低額 / 税 / 単位 / 丸めが確認済みのものだけ計算します。ポイント・cashback・併用を既存単独クーポン計算へ混ぜません。現サンプル2施策はポイント型のため、対象料金を入力しても割引額には換算しません。

Level 3の「最安」は、同じ宿・部屋・食事・人数・泊数・取消条件・税手数料・取得時点・在庫が揃った予約先だけで比較し、「確認できた予約先の中で最安」と表現します。
